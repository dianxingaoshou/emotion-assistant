# 第一阶段交付与验收

以原始方案末尾的第一阶段目标为范围：让现有电脑具备一次完整真实会话的采集、联合判断、用户确认、调节和可追溯保存能力。

| 项目 | 实现及证据 |

| 独立模型 | YuNet、EmotiEffLib、emotion2vec+、可选 SenseVoice；官方权重固定版本与 SHA256；真实样例输出在 `reports/model-smoke.json` |
| 协同 | 时间区间对齐、质量与覆盖率加权、模态缺失、冲突提示、不确定分数保留；自动化回归覆盖 |
| 调节闭环 | 用户确认、当前需要与前自评、八类分步活动、过程反馈与主动换方法、不适中止、即时和可选稍后复测、个人反馈排序；机制见 `REGULATION_LOOP.md` |

## 本次实际验证的边界

软件回归和官方样例推理已经运行；未把样例推理或模拟闭环称为真人效果实验。设备清单未发现摄像头，完整真人音视频采集、实际拔插恢复、实际退出后设备复用以及 60 分钟长测尚未验证。已枚举到的 Realtek 输入端口，也不能据此证明存在可录到本人声音的已连接麦克风。

没有执行情绪识别准确率、Macro-F1、四组消融、延迟 P50/P95 或调节有效性实验。这些结果需要授权数据和正式试验，不能由单次样例耗时或脚本自评分数推断。

## 连接设备后的真人验收步骤

1. 运行 `scripts/doctor.py` 确认摄像头和本人使用的麦克风可枚举；避免系统回录或背景多人场景。
2. 双击 `start.cmd`，选择真实设备采集和个人档案，主动勾选授权。先不开启转写，观察模型是否加载。
3. 正常看屏幕并自然说话约 3–6 秒，检查视觉和声学原始输出、输入质量及联合区间；静音时语音留缺，不出现伪中性。
4. 遮脸并继续说话，检查视觉拒识/降权及声学降级；画面出现多人时停止自动视觉归属。
5. 主动点击调节，确认需求，填写前自评，选择方法并推进步骤。分别检查“没变化”可换方法、“不舒服”立即停止；结束后填写自评和帮助程度。可主动安排稍后复测，关闭重启后核对待办保留。若没有有效复测选择缺失，检查系统未宣称改善。
6. 暂停后确认设备停止产生观察；恢复后旧语段不回灌。拔插一种设备，检查错误提示、重连和其余功能继续运行。
7. 结束并导出 JSON，核对 `mode=real`、两个模型版本、实际时间段、融合来源、自评、活动和事件；检查去重覆盖时长。
8. 关闭窗口后用其他程序打开摄像头/麦克风，确认可复用且没有残留 `emotion-*` 子进程。后续另做 60 分钟稳定性运行。

## 后续阶段

人脸身份关联、说话人验证、个人基线、正式回放消融与课程论文留在后续阶段。当前已实现可解释的反馈规则排序，仍需真实用户试验检验效果。用户管理为手动档案，不承担身份认证；语音按用户主动启用的单人麦克风采集，不声称自动区分说话人。
