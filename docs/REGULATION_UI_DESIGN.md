# 调节闭环界面约束

技术仍为 PySide6 原生桌面与 QSS，沿用 `ui_theme.py` 的森林绿、三种文字角色、SPACE/TYPE/RADIUS 令牌；没有 Tailwind、网页组件库或暗色模式。本次不更换样式体系或增加依赖。

按 `refactoring-ui` 的 C → B 流程，先识别现有界面的功能呈现缺口，再构建新增内容：

| 发现 | 规则 | 当前呈现 | 本次修改 |
| --- | --- | --- | --- |
| 活动执行缺少可操作的阶段 | §2.1、§2.5 | 一段固定说明与倒计时，用户无法确认正在做哪一步 | 展示当前步骤、步骤进度、下一步及明确的复测入口 |
| 过程反馈没有去向 | §2.8、§8.4 | 仅结束时填写帮助程度 | 提供合适、没变化、不舒服三种即时反馈；停止与换方法有明确后果说明 |
| 选择方法缺少依据 | §2.1、§2.5 | 四种活动的平铺下拉框 | 先选择需求和时间，展示三项建议及原因；仍可自主选择其他活动 |
| 完成后难以看出闭环 | §2.5、§8.4 | 仅显示前后分数和一句已保存 | 同时显示主观反馈、可比性、下一步行动、可选稍后复测；个人方法反馈可回看 |

新增界面的内容排名：当前步骤和当前阶段的一个主操作为第一层；推荐原因、自评变化与用户反馈为第二层；样本数、模式、模型可比性和来源为第三层。模型不能覆盖用户“不舒服”或“没帮助”的反馈。

宏观流程仍沿用已有四步指示器。调节页内部新增“本次调节／个人方法反馈／稍后复测”三个视图，避免把所有设置、统计和待办同时铺开。指导与复测分步展示；支持提前结束，不把倒计时到零当作改善。

像素复查发现窄窗口下，长步骤会把复测和不适停止入口推到视口外；因此把这两个原有入口移到左侧的简短活动摘要下，按 §2.8 和 §3.3 保持主要操作易于找到。个人反馈使用“有帮助次数／有效主观反馈次数”展示小样本，不用一次记录的 100% 制造确定感。历史摘要优先显示不适及延迟复测，同时在详情保留即时自评分数，避免数值变化覆盖主观反馈。

颜色和字号继续来自既有令牌，不凭感觉添加新色值。新组件使用现有卡片、辅助文字、语义提示和按钮层级。按 1280 和 1040 的桌面宽度渲染验证；375px 不属于当前原生桌面最小宽度支持范围。

## 完成后的视觉与交互复查

| 检查 | 结果与证据 |
| --- | --- |
| 层级与操作 §2.1、§2.8 | 12 个布局状态的可用主操作最多一个；指导态的复测、停止入口在 1280×900 与 1040×760 视口内完整可见 |
| 布局与分组 §3.3、§3.6 | 方法准备、当前指导、个人反馈分区；六张调节截图已目视检查，12 个桌面布局无横向溢出 |
| 字体、颜色与状态 §4、§5.7 | 沿用现有字号和颜色角色；阶段用编号、文字和进度共同表示；不适始终有明确文字，不依赖颜色 |
| 空值与样本 §8.4 | 缺失复测保留空值；反馈不足明确显示；真实与模拟来源分开；小样本帮助反馈显示实际次数 |
| 响应边界 | 375px 请求会被原生窗口最小宽度限制到 1040px，不宣称移动端支持 |

最终结果：94 项自动化回归、63 项闭环检查、46 项界面检查通过。验收均采用离屏界面与明确标记的模拟输入，不代表真实调节有效性。记录见 `reports/acceptance.json`、`reports/regulation/result.json` 与 `reports/regulation/layout/layout.json`；截图位于 `reports/regulation/`。
