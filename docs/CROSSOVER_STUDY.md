# 真人调节对照实验：参与与统计

**研究问题：** 同一个人在基础策略和自适应策略下，每小时收到多少次自己明确表示不想要的提示？接受活动后，两种策略的完成率、即时自评和稍后自评有何不同？两种条件都有调节活动，本实验比较的是两种产品策略，不把前后自评下降直接归因于活动。

## 一个人怎样参与

1. 双击 `start.cmd`。第一次可以用「模拟回放」熟悉操作，正式测试选择「真实设备采集」。检查摄像头和本人使用的麦克风。保持相同软件版本、设备和融合设置，两次都用同一个个人档案代号；不同参与者使用不同代号，无需填写真名，也不需要开启转写。
2. 在「对照实验」查看说明，自愿勾选本次参加，再按通常流程单独同意采集并开始。程序随机决定先后顺序：可能是基础→自适应，也可能反过来。不要根据第一场表现换档案重抽顺序。未勾选的普通会话不作为实验。
3. 两场建议间隔至少 24 小时，安排相近日常任务，尽量同一时段、同一环境、相同的预定时长（例如每场 30 分钟）。照常使用；不必刻意制造负面情绪，也不必凑够提示或活动次数。可以开勿扰、拒绝、暂停、主动调节或退出。
4. 程序发出提示时，有两个不同的问题：「此刻想不想收到提示」和「现在要不要调节」。可以觉得提示来得合适却不想做活动，也可以不评价打扰感受。做活动时按实际感受填写前后困扰度；稍后复测自愿参加，尽量两场采用相同的复测间隔。未发生的事、没填的分数都不要补成零。
5. 正常结束第一场；第二场继续用同一台电脑、同一档案、同一来源，重新勾选参加。收齐两场和自愿的稍后复测后，在「对照实验」查看或导出汇总。信号覆盖充分但两次都没出现提示，也是有效的使用观察。一人两场能验证操作流程，不足以说明对一般用户有效。若比较多人，先用一两位志愿者演练，在正式收集前固定招募人数、时长和统计方式，不要按效果好坏决定何时停止。

## 两种策略比较什么

基础策略和自适应策略都允许手动调节，并保留勿扰、提示上限、拒绝冷却和不适停止。对照期间改变的是提示和活动推荐策略，摄像头、识别模型、自评量表与可选活动不因分组改变。基础策略针对持续负向线索询问，沿用原先按需要、时间和偏好排列的方法；自适应还可针对持续冲突澄清，并在本场明确收到“不想要提示”反馈后一小时内暂缓主动询问。至少两条匹配情境的既往反馈才可能影响推荐顺位。新档案的两种顺位可能完全相同；可用汇总中的 `offers_where_rankings_differ` 和 `recommendation_offers` 查看两种顺序实际有多少次不同。不要为了产生差异补造历史，也不要把两种策略的总体差异单独归功于某个组件。

## 事先约定的读数

| 指标 | 读法与注意事项 |
| --- | --- |
| 主要指标：明确不想收到的提示数 / 可评价会话的非暂停小时 | 只有有效音频或视觉区间的并集至少覆盖非暂停时长的 50%，该场才进入这个指标。未评价的提示分别按全部想要、全部不想要给出上下界，无法给出确切值时留空。拒绝调节不自动算「不想收到提示」。 |
| 接受率 | 明确接受次数 / 实际发出次数；同时看拒绝和未回答的数量。没有提示时接受率留空。 |
| 活动完成率 | 以开始的活动为分母，同时报完成数、中断和缺失。完全没开始活动时没有完成率。 |
| 即时、稍后自评变化 | 方向统一为「前测困扰度减去后测困扰度」，正值表示自评下降；分别报告有配对自评的人/活动数及缺失。仅有后评、未参加或没到期的记录都不是零变化。 |

分析以人作为比较单位，报告同一人的「自适应减基础」差值；不同结果可拥有不同的有效配对人数。至少两人有成对结果时，程序用固定随机种子、按人有放回重抽 2,000 次给出探索性的 95% 区间。不要把同一人反复点过的提示当作多名独立参与者。分别查看两种先后顺序的人数；如一侧缺人、样本少、跨日情况差别大或退出集中，结果只能作探索性描述。学习了调节方法之后，第二场可能受到第一场影响，即使顺序随机也不能保证这种影响完全消失。

## 查看自己的实验结果

在「对照实验」点击「查看汇总」，需要分析时点击「导出汇总 JSON」。同一台电脑上的多个代号可一起统计；不要把不同电脑的汇总均值直接平均。在项目根目录也可读取本机数据库，得到同一口径的报告：

```powershell
.\.venv\Scripts\python.exe scripts/analyze_trial.py --mode real --out reports/trial-real.json
```

真实与模拟来源分开；演练时将 `real` 改成 `simulation`，并更改输出文件名。报告里 `by_condition` 是各条件的描述统计，`paired` 是按人配对的差值、有效人数及区间。未满两场、退出或缺失应如实报告，不补造数据。

报告只需要汇总数字；不要为复现公开个人会话、转写、录音或视频。用户可以只体验普通模式。真人结果需等自愿参与者实际完成后生成。
