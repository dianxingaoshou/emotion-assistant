**可以先完全在电脑上实现，而且能对齐图片中的四项要求；关键是把系统做成“表情与语音共同判断—用户确认—调节执行—效果复测”的完整闭环，并用对照实验和异常测试证明有效协同，而不是把几个模型的结果并排显示。**

建议电脑端第一版采用：**电脑摄像头＋电脑麦克风＋Python桌面程序＋本地模型＋本地数据库**，暂时不接MaixCAM、不依赖云服务、不把大语言模型作为必需组件。

下面这套方案可以作为开发任务书和报告框架。文中帧率、时间窗、延迟等数值均为**初始工程参数或验收目标，需在你们的电脑上实测，不是已获得的性能结果**。

## 一、先明确：四项课程要求如何落实

| 至少两个模型有效协同 | 表情模型和语音情绪模型共同参与同一时间段的判断；画面或声音质量改变时，融合权重和后续动作随之改变 | 单视觉、单语音、固定融合、质量感知融合的对照实验 |

## 二、真实场景与第一版功能范围
### 场景定位
建议聚焦为：

> **面向自愿使用的成年用户，在电脑前学习或工作时，记录可观察的情绪线索，在用户需要时提供短时自我调节工具，并记录哪些方法更符合个人反馈。**

例如，用户调试程序时连续表现出烦躁的语气，并主动表示“这个问题一直解决不了”。系统结合表情与语音线索，询问是否需要暂停；用户确认后，选择短时休息或任务拆解；结束后再次自评，系统保存本次反馈。

不要把目标写成“通过摄像头准确识别用户真实心理状态”。面部动作与内心情绪并非一一对应，同一种表情在不同情境中可能具有不同意义，因此产品应显示“观察线索”和“不确定性”，而不是诊断结论。[Association for Psychological Science](https://www.psychologicalscience.org/journals/pspi/1529100619832930/?utm_source=chatgpt.com)

### 第一版应完整实现的功能
| 功能 | 第一版的具体范围 |
|---|---|
| 用户管理 | 创建个人档案，支持手动选择用户；自愿注册后可做人脸关联 |
| 视频分析 | 实时摄像头、人脸检测、表情分析、画面质量检测 |
| 语音分析 | 电脑录音、语音分段、语音情绪分析、语音转文字 |
| 联合判断 | 时间对齐、质量加权、模态缺失处理、冲突提示 |
| 连续记录 | 情绪线索时间线、语音片段记录、自评记录、有效观察时长 |
| 调节建议 | 提供少量审核过的活动，用户自主选择、拒绝和中止 |
| 效果评估 | 调节前后自评、可比的模型观察、主观帮助程度 |
| 个性化 | 根据个人基线、用户偏好和历史反馈调整提示及推荐顺序 |
| 工程保障 | 暂停采集、设备重连、模型超时降级、数据删除、日志导出 |

第一版不做心理疾病诊断，不做多人会议分析，也不承诺理解所有反讽、引用和复杂语义。**这些边界不妨碍形成完整可用的闭环。**

## 三、电脑端技术架构与模型选型
### 采用单机桌面程序
建议主技术栈为：

**Python＋PySide6桌面界面＋OpenCV视频采集＋sounddevice录音＋PyTorch/ONNX推理＋SQLite存储。**

这版不必同时维护Vue前端、Web服务和浏览器录音。采集、推理和业务逻辑直接在电脑运行，后续需要网页端时再拆出服务接口。

电脑先使用现有配置。可以把16 GB内存作为开发资源预算，但不要将其视为已经验证的最低配置；是否需要独立显卡，由单模型与整机基准测试决定。

### 模型选型
| 模块 | 建议使用 | 主要职责 |
|---|---|---|
| 人脸检测、身份关联 | **YuNet＋SFace** | 检测人脸、对齐、关联已注册用户；不负责情绪判断 |
| 核心模型M1 | **EmotiEffLib：`enet_b0_8_best_afew`** | 输出人脸表情类别分数 |
| 核心模型M2 | **emotion2vec+：`emotion2vec_plus_seed`** | 输出语音情绪类别分数 |
| 辅助模型M3 | **SenseVoiceSmall** | 将中文语音转写为文字 |
| 语音活动检测 | **Silero VAD** | 找到说话区间，不把静音送入声学情绪判断 |

OpenCV官方提供人脸检测与识别接口；EmotiEffLib提供上述表情模型及相应使用方式。模型预处理必须按各自实现执行，不能随意统一图片尺寸、颜色顺序和归一化方法。[OpenCV Documentation](https://docs.opencv.org/4.13.0/d0/dd4/tutorial_dnn_face.html)

emotion2vec+提供包含`other`、`unknown`在内的情绪分类输出，官方示例输入为16 kHz语音；SenseVoiceSmall支持中文转写等任务；Silero VAD支持16 kHz音频。[Hugging Face](https://huggingface.co/emotion2vec/emotion2vec_plus_seed)

这里要明确三个关系：
- **M1和M2是满足“有效协同”的主模型。**二者都必须影响融合判断或后续提示，不能只是各显示一个标签。
- **M3负责记录语言内容，不等于已经理解语言。**首版通过用户确认“是否在表达自己的当前感受”，处理引用、朗读等歧义。
- SenseVoice本身也有情绪标签能力，但本方案不把它与emotion2vec重复计为两份独立声学证据。[GitHub](https://github.com/QwenAudio/SenseVoice/blob/main/README.md?utm_source=chatgpt.com)

## 四、核心运行流程：从采集到共同判断
### 1. 启动、授权与个人档案
打开软件后先选择摄像头、麦克风，检查画面和音量，再选择“开始本次会话”。

用户可以手动选择个人档案，也可以自愿注册人脸。注册阶段采集若干张清晰、轻微不同角度的人脸，保存身份特征；身份匹配不确定时要求用户确认，不自动归入“最相近的人”。

**人脸关联只用于避免记录混淆，不作为查看私密记录的唯一安全认证。**

### 2. 持续采集，但按需推理
| 数据 | 初始设置 | 处理方式 |
|---|---|---|
| 摄像头 | 640×480、约15 FPS | 预览保持流畅，表情推理只取每秒2～5帧 |
| 麦克风 | 分析输入统一为16 kHz、单声道 | 实际设备采样率不同时进行真正的重采样 |
| 语音分段 | 约0.6秒静音结束，长语音约8秒切段 | 片段结束后分别送入转写和声学模型 |
| 短语音 | 不足约2秒时降低声学结论的可信程度 | 可以转写，但允许返回“声学证据不足” |
| 临时缓存 | 最近约60秒 | 默认只保留短期缓存，不长期保存全部原始媒体 |

录音回调只负责把音频写入预分配缓冲区，不在回调中运行模型或写文件。sounddevice官方明确要求避免在实时音频回调中执行阻塞或耗时不可预测的操作。[Python Sounddevice](https://python-sounddevice.readthedocs.io/en/latest/api/streams.html)

### 3. 时间对齐，防止“拿过去的声音配现在的表情”
每条结果至少包含：

```text
session_id、event_id、t_start、t_end、processed_at、
modality、scores、quality、valid、reason、model_version
```

建议分成两种更新：

**实时视觉更新：**每秒聚合最近几秒的表情结果，界面明确标为“仅视觉观察”。

**音视频联合更新：**某段语音结束后，提取它实际起止时间内的视觉结果进行融合。语音推理晚到，就更新对应历史区间，不能拿此时的新画面来融合，也不能把旧语音状态无限延续。

电脑统一管理时间基准；设备时间需要映射到同一会话时钟。联调时用画面内拍手和录音声响检查偏移。无法准确对齐时，降低融合可信程度或暂时只显示各模态结果。

### 4. 先判断输入能不能用，再判断情绪线索
为每个模态建立质量评分，评分是工程指标，不是“情绪判断正确的概率”。

| 模态 | 质量检查依据 | 无效时处理 |
|---|---|---|
| 视频 | 是否有人脸、脸框尺寸、模糊、亮度、明显偏转、跟踪连续性 | 不参与融合，标记原因 |
| 音频 | 有效语音时长、削波、音量异常、背景噪声估计、是否系统播放音频 | 降权或不参与融合 |
| 身份归属 | 是否单人、是否主动录音、是否存在归属疑问 | 暂停写入个人声学记录 |
| 时间 | 数据是否过期、是否属于同一区间 | 不强行融合 |

**特别注意：检测到人脸不等于麦克风中的声音来自这个人，VAD也不负责说话人身份识别。**因此第一版限定单人场景；共享空间或背景对话明显时，切换“按住说话/主动记录”模式。没有说话人验证模块，就不能宣称解决了自动多人语音归属。

### 5. 两个模型如何真正协同
不同模型的标签不完全一致，不能直接把原始分数数组相加。建议保留原始结果，同时映射到四种统一线索：

**正向、中性、负向、不确定。**

例如，把`happy`映射为正向；明确的负向类别归为负向；`surprised`、`other`、`unknown`等不强行归为正负。**不确定部分必须保留，不能删掉后重新归一化，制造出高置信度结果。**

通过最低质量检查后，采用质量加权：

\[
p_{\text{fusion}}
=
\frac{m_v\alpha_vq_vp_v+m_a\alpha_aq_ap_a}
{m_v\alpha_vq_v+m_a\alpha_aq_a}
\]

其中，\(p_v、p_a\)为统一标签空间下的模型分数，\(q_v、q_a\)为质量分数，\(m_v、m_a\)表示模态是否有效，\(\alpha_v、\alpha_a\)为在验证集上调整的基础权重。分母为零时返回“无法判断”。

**归一化权重不等于整体可信度。**即使只有一个模态，也必须达到最低质量要求，不能因它获得100%的相对权重就显示“高度可信”。

一个仅用于解释机制的例子：阴影下的表情负向分数为0.8、视觉质量为0.1；清晰语音的负向分数为0.2、声音质量为0.9。在基础权重相等时，融合负向分数为0.26，而不是直接平均得到0.5。是否据此提示，还要检查不确定性、冲突和持续时间。

对应决策建议如下：

| 两种模型的结果 | 系统动作 |
|---|---|
| 两者有效、方向一致 | 提高该线索的提示优先级，但仍由用户确认需求 |
| 视频质量差、声音有效 | 以声音为主，显示“视觉不可用/降权” |
| 没有说话、视频有效 | 只显示视觉观察，不填入“中性语音” |
| 两者明显冲突 | 标记不一致，询问用户当前感受 |
| 两者均无效 | 显示数据不足，不生成状态分数 |

这才是协同：**一个模型的结果或质量发生变化，会改变联合判断、提示方式或是否请求确认。**

## 五、连续量化、调节与效果复测
### 量化哪些内容
第一版不建议合成一个“心理健康总分”。分别显示：

**负向线索分数：**定义为\(N_t=100p_t(\text{负向})\)，仅用于观察模型输出变化；不确定性高时不展示确定分数。

**主观困扰度：**由用户选择0～10分，记为\(D_t\)，这是用户当前感受的直接反馈。

**数据覆盖率：**显示有效视觉时长、有效语音时长、联合观察时长与缺失区间。

例如，60分钟会话只有5分钟有效语音，就不能把剩余55分钟都解释为“情绪中性”。滑动窗口有重叠，统计时长时要去重。

个人基线可以从若干次用户自述较平稳的会话中逐步建立。首次几分钟只作为临时参考；视觉单模态与音视频联合结果分别建立参考范围，不混在一起比较。

### 用状态机控制调节
```text
观察
→ 用户主动请求，或系统发现持续线索
→ 用户确认是否需要帮助
→ 调节前自评
→ 选择并执行活动
→ 调节后自评与复测
→ 保存反馈、更新推荐历史
→ 冷却期
→ 返回观察
```

第一版可先设置：短暂单次异常不提示；持续变化达到约20秒后才考虑询问；拒绝后进入冷却期，默认20分钟内不重复同类主动提示。上述数值是待验证的交互参数，不能作为医学阈值。

同一语音片段被多个滚动窗口引用时，不能当成多次独立证据；用户主动点击“我想调整一下”则随时可进入流程，不需要模型批准。

### 建议内容先做少、做完整
| 用户确认的需求 | 提供的活动 | 软件实际执行 |
|---|---|---|
| 想暂停一下 | 短时休息 | 倒计时、暂停任务提醒、返回时复测 |
| 感到紧绷，愿意尝试 | 舒适呼吸引导 | 可关闭声音的视觉节奏，可随时停止 |
| 注意力陷在烦恼中 | 简短感官注意练习 | 按步骤引导关注当前环境 |
| 任务卡住 | 任务拆解 | 让用户填写卡点、已尝试方法和下一步行动 |

呼吸练习应遵循舒适、不强迫的原则；感官注意活动可参考WHO的压力自助材料。引入这些活动不代表已经证明你们的软件具有治疗效果。[nhs.uk](https://www.nhs.uk/mental-health/self-help/guides-tools-and-activities/breathing-exercises-for-stress/?utm_source=chatgpt.com)

第一版的任务拆解可以用结构化表单和固定模板，不必让大模型自由生成建议。转写文本可以由用户勾选“这是我当前的困扰”，避免仅因朗读了一句负面内容就触发调节。

### 怎样判断“这次有没有帮助”
调节前记录困扰度\(D_{\text{pre}}\)，调节后记录\(D_{\text{post}}\)：

\[
\Delta D=D_{\text{pre}}-D_{\text{post}}
\]

正值表示本次自评困扰下降，负值表示上升；另外记录“觉得有帮助/无明显帮助/更不舒服”。

模型输出只作辅助观察，前后必须尽量使用相同条件和模态组合。系统播放引导音频的区间不参与用户声学评分；闭眼、离开镜头或停止说话造成的数据缺失，也不能被视为改善。

结果应明确区分：

**用户自评改善；用户未感到改善；用户感到更差；缺少有效复测，无法评价。**

不要用“模型检测到笑容增加”覆盖用户“没有改善”的反馈，也不要仅凭一次前后下降宣称某种方法有效。

### 自适应先采用可解释的规则
为每种活动保存：使用次数、有效复测次数、平均自评变化、完成率、拒绝次数、不适记录和用户偏好。

下次推荐按以下顺序处理：

**排除用户不接受或曾引起不适的活动 → 匹配当前需求与可用时间 → 参考相似情境下的历史反馈 → 让用户选择。**

数据少时显示“反馈不足”，不称为“最佳方案”。这样已经实现了可解释的个性化，不需要首版就引入强化学习。

## 六、工程实现与可用性保障
### 模块划分
| 模块 | 建议代码位置 | 必须输出的结果 |
|---|---|---|
| 采集 | `capture/` | 带时间戳的画面和音频、设备状态 |
| 模型推理 | `models/` | 原始分数、质量、有效性、模型版本 |
| 对齐与融合 | `fusion/` | 区间级联合结果、模态状态、冲突标记 |
| 调节策略 | `intervention/` | 触发原因、状态流转、活动记录、复测结果 |
| 数据管理 | `storage/` | 会话、观察、转写、自评、策略历史 |
| 桌面界面 | `ui/` | 实时页、调节页、统计页、设置页 |
| 测试与监测 | `evaluation/` | 回放工具、延迟记录、故障测试、对照实验 |

### 并发设计
界面主线程只更新界面；摄像头采集、音频处理、视觉推理、语音推理和数据库写入使用独立工作单元。PySide6可通过工作线程与信号传递结果，不能让耗时推理堵塞界面事件循环。[Qt Documentation](https://doc.qt.io/qtforpython-6/overviews/qtdoc-threads-technologies.html?utm_source=chatgpt.com)

队列需要有上限：视频推理跟不上时丢弃旧待处理帧、保留新帧；音频积压或丢失则必须记录缺口，并在界面显示。推理超时不能让整个程序卡住，大模型增强模块即使以后加入，也不能成为采集链路的阻塞点。

所有模型先运行官方单模型示例，再集成。跑通后锁定依赖版本、模型版本和权重文件校验值，不在答辩前自动更新。

### 数据与隐私
建议数据库至少包含：
`users、sessions、observations、utterances、self_reports、interventions、strategy_stats`。

默认长期保存结构化结果；转写文本、原始录音、人脸注册分别征求授权。原始视频不默认长期保存。用户应能一键暂停、结束会话、删除记录和删除人脸模板；日志中避免输出完整转写及身份特征。

关闭程序时必须停止录音、释放设备、结束工作线程；“界面关了，麦克风还在工作”应作为必测故障。

### 界面应当展示什么
实时页不能只有“开心/难过”标签。建议同时展示：

**视频预览、转写、两种模型的结果、当前模态是否有效、融合趋势、判断依据、用户修正按钮、暂停按钮。**

统计页展示会话时长、有效覆盖率、线索趋势、自评变化和活动反馈。数据缺口保留为空白，不画成一条看似正常的连续曲线。

## 七、实验与报告：证明“不是模型简单拼接”
### 先做四组消融对照
使用同一批授权采集的桌面场景音视频进行回放，比较：

| 实验组 | 配置 | 要回答的问题 |
|---|---|---|
| A | 仅表情模型 | 视觉单独工作有哪些问题？ |
| B | 仅语音情绪模型 | 声音单独工作有哪些问题？ |
| C | 两模型固定权重融合 | 简单融合是否有帮助？ |
| D | 质量感知融合＋缺失/冲突处理 | 遮挡、噪声等情况下，设计是否减少错误判断？ |

再把个人基线或反馈推荐作为后续增强实验。比较模型时保持采集数据、阈值选择流程和评价条件一致；有用户确认的完整系统应单独评价，不能把人工确认带来的收益全部算成模型准确率。

标注要分清两件事：外部观察者可以评价“外显表情/语气线索”，用户自评用于反映主观感受，二者不是同一种标准答案。测试集应按参与者或独立会话划分，不把同一视频的相邻帧随机拆开训练和测试。

可报告Macro-F1、混淆矩阵、与用户自评的一致性，同时报告**拒识率和覆盖率**。不能通过大量输出“不确定”换取漂亮准确率，却不披露实际能判断多少数据。

**融合效果优于单模态是需要验证的目标，不是可以提前写进结论的事实。**提升也可能体现为更少的错误提示、更好的异常处理，而不只是干净数据上的分类分数。

### 鲁棒性与边界测试
| 测试输入 | 预期行为 |
|---|---|
| 用户全程不讲话 | 保留视觉观察，语音标记缺失 |
| 遮脸、侧脸、低照度 | 视觉降权或拒识，不输出确定结论 |
| 画面出现多人 | 暂停自动个人关联或请求确认 |
| 有背景人声 | 明确首版归属能力边界，切换主动录音，不声称已自动识别说话人 |
| 用户朗读负面句子 | 由用户确认是否为当前自述，不直接触发调节 |
| 系统播放提示音或引导语 | 排除相应区间的用户声学评分 |
| 摄像头/麦克风断开 | 显示错误，其他可用模块继续运行 |
| 模型推理超时 | 标记该结果不可用，不冻结界面 |
| 用户否认判断或拒绝建议 | 保存修正并停止重复打扰 |
| 调节后没有有效数据 | 显示无法评价，不宣布改善 |

### 性能分析怎么做
每个事件记录“采集、排队、预处理、推理、融合、显示”的时间，至少测以下项目：

| 指标 | 测量方式 | 初始验收目标 |
|---|---|---|
| 视觉端到端延迟 | 采集到界面更新，统计P50/P95 | P95争取不超过1秒 |
| 语音结果延迟 | 语音片段结束到结果显示 | P95争取不超过5秒 |
| 音频实时因子 | 总处理耗时÷音频时长 | 持续处理时平均小于1，避免积压 |
| 资源占用 | CPU、内存，使用GPU时加显存 | 长时间运行不出现持续无界增长 |
| 运行稳定性 | 连续运行、异常恢复、丢帧与丢音记录 | 至少完成60分钟稳定性测试 |
| 交互负担 | 每小时提示数、拒绝比例、完成率 | 验证提示频率是否可接受 |

报告必须注明电脑配置、模型版本、输入分辨率、音频片段长度和并发条件。模型官方基准不能当作你们电脑的实测成绩。

### 调节效果如何做探索性验证
可以招募约10～15名自愿成年参与者，比较同等时长的“安静休息”和“一种系统引导活动”，尽量平衡先后顺序，记录前后自评、帮助程度和不适情况。按学校要求处理知情同意及伦理程序，允许随时退出，不诱导强烈负面情绪。

这只能作为小规模可用性和初步效果探索。**单次前后下降可能来自自然恢复、休息或期待，不能直接归因于系统。**统计单位应是参与者或独立会话，不是成千上万个重叠窗口。

### 报告建议结构
报告按“需求与场景—系统架构—模型与协同机制—闭环调节—工程实现—实验结果—局限与改进”组织即可。

其中，架构图展示模块和数据流；时序图展示一段语音如何关联对应表情；状态机图展示调节前后流程；性能图展示延迟和资源；消融结果说明协同设计到底贡献了什么。

## 八、开发优先级：先把闭环做通，再追求复杂度
| 优先级与阶段 | 具体交付物 | 验收后再进入下一阶段 |
|---|---|---|
| **P0：采集底座** | 摄像头预览、麦克风选择、录音分段、统一时间戳、暂停与退出 | 能连续采集，关闭后设备确实释放 |
| **P0：独立模型** | 人脸检测、表情、声学情绪、转写；人脸关联可先用手动档案替代 | 两条情绪模型都能处理真实采集数据 |
| **P0：协同闭环** | 时间对齐、融合、趋势、自评、活动、前后测、数据库 | 完整保存一次“观察—确认—调节—复测”事件 |
| **P1：可用性与个性化** | 人脸关联、质量门控、冲突处理、个人基线、反馈排序、数据删除 | 遮脸、静音、断连等情况下不会产生虚假的正常值 |
| **P1：验证与交付** | 回放工具、消融实验、性能测试、边界演示、报告 | 所有结果有配置、数据和日志可追溯 |
| **P2：扩展** | 复杂语义理解、说话人验证、MaixCAM接入 | 不影响已完成的核心功能 |

这套方案最值得突出的创新点是：**能判断证据是否可靠的双模态融合、允许用户纠正的个体化判断、根据真实反馈更新的调节闭环。**它们属于可验证的应用系统创新，不需要包装成“首次提出”的算法。

**第一阶段就把目标定为“现有电脑完成一整次真实使用会话，并留下完整、可追溯的判断和调节记录”；做到这一点后，再用异常测试和消融实验补齐课程要求，比先堆更多模型或接入MaixCAM更有价值。**
