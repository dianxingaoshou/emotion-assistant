# Refactoring UI 界面精修记录

本次采用 `refactoring-ui` 的 C 流程：先 D 审查，再按“层级 → 布局与间距 → 排版 → 色彩 → 深度 → 图像 → 收尾”修正。没有更换技术栈、品牌风格或安装依赖。

## 检测与约束

- 技术：Python 3.12、PySide6 原生桌面、QSS；不是 SSR/SPA，没有 Tailwind 或网页组件库。
- 既有系统：`ui_theme.py` 的森林绿主题；保留品牌 `#1F7665`、侧栏 `#173A36` 和浅色背景。平面设计无阴影属于现有选择，不列为缺陷。
- 缺失系统：字号和间距没有统一命名；同一含义的文字颜色散落在 QSS、内联样式和 QPainter。
- 内容优先级：实时观察与对应证据为主，两个模态和输入预览为辅，模型技术信息为第三层。每个页面只保留一个主操作，操作随状态切换。
- 暗色模式：未实现，本次不扩展。
- 验证：原生窗口实际渲染 1280×900、1040×760；375px 请求受到既有最小宽度限制，实际为 1040px。移动网页不属于本项目支持范围，不将这个探测伪称为移动适配。

## 令牌与验证方法

现有品牌、背景和破坏性操作颜色优先保留；新增中性/品牌/警示色阶由技能自带 `generate_palette.py` 以现有基色生成。常规文字仅使用主文字、次文字、辅助文字三个语义层级，状态和深色侧栏另用明确的语义前景色。停用控件、装饰网格和分隔线不当作普通文字对比度样本。

脚本 `scripts/ui_review.py` 生成实际 Qt 截图和布局记录；`reports/refactoring-ui/before/` 保存修改前像素证据，`before-source/` 保存源码用于生成可审查差异。修改后的图片、对比度矩阵、差异和最终结果同目录集中保存。

## 修正结果

上述 7 项发现均已对应修改：当前页面的主操作按状态突出；调节摘要按内容定高；转写关闭和空历史采用简洁的空状态；字号、间距和文字角色共享令牌；趋势有线型和形状图例；历史数值列右对齐。保留现有数据含义、确认流程和模型逻辑。

本次核验的 **47 组可用文字/背景配对全部通过 4.5:1 阈值，最低 4.5645:1**。矩阵包含侧栏、控件占位文字、表格、图例、步骤、呼吸引导和提示状态；停用控件与装饰图形不冒充普通文字样本。配对明细位于 `reports/refactoring-ui/contrast-after.json`，技能原脚本的输出为 `contrast-after.txt`。这份结果表示所声明配对通过，不是对所有操作系统与显示器的全面无障碍认证。

- 55 项软件回归通过，45 项界面闭环检查通过。
- 1280×900、1040×760 各 6 个状态，共 12 张截图；均无横向溢出，启用且可见的主操作每页最多一个。小窗口按既有桌面约束纵向滚动。
- 实际 Qt 占位文字为 `#627268`，实际像素字号角色为 `12 / 16 / 20 / 26 / 34 / 44`。
- 本次只使用明确标记的模拟数据与内存数据库，没有打开摄像头/麦克风或运行模型，不计作真人效果验证。

统一结果：`reports/refactoring-ui/verification.json`。可审查代码差异：`reports/refactoring-ui/ui-changes.diff`。
