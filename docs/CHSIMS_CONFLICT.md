# 中文视频中三路线索冲突时，千问复核能提供什么？

**48 段真实中文视频中，离线文字参照判对 20 段，加入千问冲突复核后判对 21 段。** 有 6 段得到纠正，另有 5 段从对变错。准确率净增 2.08 个百分点，按来源重抽样得到的 95% 区间为 −9.62 至 +14.89 个百分点，配对精确 McNemar 检验 p=1.000。本次结果支持将复核作为可查看、可质疑的第二意见；要判断准确率有无稳定提升，还需要更多独立视频。

## 同一批视频的实测

| 方案 | 判对 | 判错 | 暂缓 | 全体准确率 | Macro-F1 |
|---|---:|---:|---:|---:|---:|
| 固定预测训练集多数类“负向” | 26 | 22 | 0 | 54.17% | 0.2342 |
| 离线中文文字参照，关闭千问 | 20 | 28 | 0 | 41.67% | 0.2932 |
| 可用模态按质量与覆盖投票 | 22 | 26 | 0 | 45.83% | 0.3543 |
| 千问只看文字，沿用相同冲突触发窗口 | 19 | 29 | 0 | 39.58% | 0.2849 |
| 千问读取同段原话和可用声画摘要 | 21 | 27 | 0 | 43.75% | 0.2978 |

全部 48 段均成功自动转写，总计 68 个可对齐话段。实际观测条件下，31 段视频中的 34 个话段触发复核，34 次返回均通过结构与引文校验。在触发的 31 段中，关闭千问、千问只看文字、千问读取声画摘要分别判对 **13、12、14** 段。其余 17 段均维持同一判断，判对 7 段。按视频计，24 段至少有一个话段取得全部三路可用分数，关闭和开启复核分别判对 11 和 14 段。

在固定触发位置后，给千问增加声画摘要多判对两段。两组各自独自判对 6 段（含声画）和 4 段（仅文字），p=0.754，按来源重抽样的准确率差值 95% 区间为 −6.78 至 +16.22 个百分点。多数类参照虽然得到最高准确率，但从未判出任何正向或中性，Macro-F1 为 0.2342。多路投票在本组的准确率和 Macro-F1 均高于千问复核，值得保留作后续对照。

**模型发现的冲突与人工标出的冲突有差别。** 根据官方文本、声音和画面三路人工参考的正负号分组，有 25 段的人工判断存在分歧。在这个子集中，离线文字参照判对 8/25，千问读取声画摘要后判对 6/25。另有 23 段的人工三路符号一致，两者分别判对 12/23 和 15/23。人工分路标签只在预测结束后用于分组；模型会对一些人工较一致的样本产生分歧，也可能错过人工标出的分歧。

同样的改判机制在两条真实片段中产生了相反后果。对 `video_0025/0017`，同段模型给出“文字中性、声学负向、表情负向”，千问把中性改为负向，符合人工整段参考。对 `video_0054/0041`，三路为“文字中性、声学正向、表情正向”，千问改判正向，而人工整段参考为中性。这解释了界面保留原始线索、候选和核对问题的原因。[逐片段与逐话段结果](results/chsims-conflict.json)

### 缺失条件

| 同样的 48 段视频 | 发生复核的视频 | 关闭千问，对/错/缓 | 开启千问，对/错/缓 | 开启后的覆盖率 | 开启后的 Macro-F1 |
|---|---:|---:|---:|---:|---:|
| 按视频实际可用线索运行 | 31 | 20 / 28 / 0 | 21 / 27 / 0 | 100% | 0.2978 |
| 去掉声学，保留相同转写和画面 | 18 | 20 / 28 / 0 | 23 / 25 / 0 | 100% | 0.3139 |
| 去掉表情，保留相同转写和声学 | 21 | 20 / 28 / 0 | 21 / 27 / 0 | 100% | 0.3219 |
| 去掉文字 | 0 | 0 / 0 / 48 | 0 / 0 / 48 | 0% | 0.0000 |

去掉声学后多判对的三段对应 p=0.453，样本规模尚不足以支持优先移除声音。缺文字时，“说了什么、表达什么方向”的复核全部暂缓。独立的原始声画检测仍在 36 段找到合格声音、39 段找到合格面部画面，45 段至少保留一项，38 段有大于零的已接受声画时长。仅看转写时段内可用声画的质量加权投票，得到 17 对、23 错、8 暂缓。发言语义与可观察的声画方向应在界面和报告中分开解释。

旧版偏英文的整段发言极性摘要在这批中文视频上给出 48 次暂缓。新的中文文字参照取自已有文字愉悦度模型，可在全部 48 段上给出方向，故能区分“补上中文输出”与“千问对已有中文判断的额外贡献”。全部条件共享 95 个不同的本机推理输入，相同输入只计一次。分类参考是影视片段标注，不能据此推断真人调节是否有效。

## 数据与比较方法

本次使用清华团队发布的 **CH-SIMS 原版**。作者为影视剧和综艺短片分别标注文本、声音、画面和整段情感倾向。研究对象是片段表达的正向、中性或负向。人物内心感受及用户调节效果需要单独测量。[作者数据页，下载表中的 CH-SIMS 行](https://thuiar.github.io/sims.github.io/chsims) · [ACL 2020 原论文](https://aclanthology.org/2020.acl-main.343/)

1. **固定样本。** 官方划分包含 1,368 条训练、456 条验证、457 条测试。在查看预测前固定规则，将测试片段按 `SHA256("chsims-conflict-v1|" + video_id + "/" + clip_id)` 升序排列，取前 48 条。每种方案沿用这 48 段。它们来自 26 个来源，人工整段参考为 26 段负向、8 段中性和 14 段正向。官方测试集无须重新切分，也没有用它训练模型或选择阈值。
2. **按上传文件实际处理。** 从官方 `Raw.zip` 获取入选 MP4，逐个核对 ZIP CRC，然后调用桌面上传入口使用的 `analyze_media(transcribe=True)`。SenseVoice 自动转写，声学模型和表情模型从原始声音、画面提取线索。每条转写按段 ID、开始和结束时间与声画输出精确匹配。人工字幕、分路标签、整段标签均不进入预测或提示词。
3. **关闭和开启千问。** 基线使用中文离线文字模型的 1–9 愉悦度，将小于 4.5、介于 4.5 到 5.5（含端点）、大于 5.5 分别映射到负向、中性、正向。开启复核的实验条件只在有有效原话且同段可用线索的判断不同时调用本机 Qwen3:8b。模型读取转写与分路得分、质量和覆盖，输出候选及逐字引文。模型主动表示依据不足计为该段暂缓；服务或格式失败保留基线。桌面端由用户选择是否复核，并列显示来源。实验为测量所有触发机会，对每个满足条件的话段都请求复核。
4. **整段计分。** 同一视频有多条转写时，分别将每个获判话段的有效时长累加到对应类别，时长最多者成为该视频的候选。全部暂缓或时长并列时整段暂缓。基线、加权投票和复核都用相同规则。评测同时报告全体准确率、包含暂缓漏判的三类 Macro-F1，以及双方都给分的共同子集。高覆盖时与低覆盖时的已判准确率不能直接比较。
5. **额外参照。** 将文字投票权重固定为 1，声学和表情各自按质量乘覆盖率投票，在同一话段中选择权重之和最高的类别，并列则暂缓。训练集最多的类别也作为固定参照。文件中原有偏英文的内容摘要另行统计。所有方法使用相同人工整段标签评分。
6. **遮蔽与真实缺失。** 先在实际可获取的线索上计算结果，再分别移除声学、表情或文字分支。遮蔽声学时保留已生成的相同转写，模拟另有文字稿；这不等于从无声视频自动生成字幕。遮蔽文字时删去原话与文字得分，禁止千问使用转写。三种遮蔽均是软件消融。真实检测中因无人脸、低质量或不确定而缺少的分路仍保持缺失。
7. **隔离声画摘要的作用。** 另设“同一触发窗口、千问只看文字”一组。先按全线索条件选定冲突话段，然后在这些话段向同一模型提供相同原话和文字读数，移除声音和表情读数。模型仍须按同一任务输出表达极性和逐字引文，核对问题只允许指向仍可见的线索。未触发的窗口保持相同基线输出。该条件用于研究对照。

此接口输出三个表达方向或暂缓。实验保留这个输出定义，因此报告分类和覆盖指标。评价连续强度的 MAE、Pearson 需要另设经过标定的连续输出，本次三分类成绩无法回答那个问题。

## 如何复现

在项目已配置文件识别模型、本机已安装 `qwen3:8b` 且 Ollama 服务已启动的 Windows 环境运行：

```powershell
.\.venv\Scripts\python.exe scripts/chsims_samples.py
.\.venv\Scripts\python.exe scripts/benchmark_chsims_conflict.py --output reports/chsims-conflict.json
.\.venv\Scripts\python.exe scripts/benchmark_chsims_conflict.py --replay --output reports/chsims-conflict-replay.json
```

下载器使用官方原始包的 HTTP 字节范围，只取固定样本。48 段 MP4 合计 223,979,962 字节。使用已有官方文件时，可跳过第一条命令并传入 `--data`，目录应有原版无表头的 `label.csv` 及 `Raw/video_NNNN/NNNN.mp4`。私有缓存包含原始转写，默认保存在 Git 忽略的 `.runtime/chsims`。正式运行和缓存回放都会检查视频、声画和 ASR 模型、项目权重、生产代码指纹，并验证千问本地清单与权重分片。项目隔离的千问模型默认位于 `models/ollama`；使用其他 Ollama 模型目录时可设置 `OLLAMA_MODELS`。公开文件提供样本编号、视频 SHA-256、逐条件决定、模型摘要和汇总统计。[机器可读结果](results/chsims-conflict.json)
